# 함께메모

**친구와 함께 쓰는 대화형 메모장**입니다.
HTML/CSS/JS만으로 되어 있어 빌드 없이 GitHub Pages에 바로 배포할 수 있고, 데이터는 Supabase에 저장됩니다.

## 동작 방식

| 요구사항 | 구현 |
|---|---|
| 누구나 가입 | 이메일 + 비밀번호로 누구나 회원가입 |
| 서로 친구가 된 사람은 **친구** 버튼에서 목록으로 보임 | 이메일로 친구 요청 → 상대가 수락하면 **서로** 친구가 되어 양쪽 친구 목록에 나타남 |
| **메모장** 버튼 → 내가 접근 권한을 가진 메모장 목록, 클릭하면 주고받은 메시지 표시 | 목록에 최근 메모 미리보기·시간·안 읽은 수 표시. 열면 대화형으로 메모가 표시됨 |
| 새 메모장 추가 + 친구에게 권한 부여. 친구라도 모든 메모장에 접근 가능한 것은 아님 | 메모장을 만든 사람(방장)이 **친구 중에서 골라** 초대한 사람만 접근 가능. DB의 RLS 정책으로 강제 |
| 메모장 안에서 누가 썼는지 보임 | 말풍선마다 작성자 이름·프로필·시간 표시, 참여자 목록, 초대·퇴장 안내 메시지 |

> 권한 검사는 화면이 아니라 **DB(RLS)에서 강제**됩니다. 초대받지 않은 사람은 친구라도, 개발자 도구로 직접 API를 호출해도 메모장과 메모를 읽거나 쓸 수 없습니다.

## 권한

| | 메모 읽기·쓰기 | 친구 초대 | 내보내기 | 이름·색 변경 | 메모장 삭제 | 남의 메모 삭제 |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| 방장 (만든 사람) | ✅ | ✅ (내 친구만) | ✅ | ✅ | ✅ | ✅ |
| 참여자 (초대받은 친구) | ✅ | ❌ | ❌ (본인 나가기만) | ❌ | ❌ | ❌ (본인 메모만) |
| 초대 안 된 친구 / 그 외 | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |

- 새로 초대된 사람은 그 메모장의 이전 메모도 볼 수 있습니다.
- 친구를 삭제해도 이미 함께 쓰는 메모장은 유지됩니다. 필요하면 방장이 내보내면 됩니다.

## 화면 구성

- **왼쪽 메뉴**: 친구 / 메모장 / 내 프로필 / 로그아웃 (받은 친구 요청·안 읽은 메모 수 배지)
- **친구**: 내 프로필(이름·상태메시지), 받은 친구 요청(수락/거절), 보낸 요청(취소), 친구 목록
  → 친구를 누르면 프로필, 함께 쓰는 메모장, "이 친구와 새 메모장 만들기", 친구 삭제
- **메모장**: 메모장 목록 → 누르면 오른쪽에 대화형 메모 화면
  - 상단: 메모장 이름, 참여자 수와 얼굴, 메모 검색, 참여자·설정(≡)
  - 가운데: 날짜 구분, 작성자 이름·말풍선·시간, 초대/퇴장 안내
  - 하단: 메모 입력 (Enter 전송, Shift+Enter 줄바꿈)
  - 참여자·설정: 이름·색 변경, 참여자 목록, 친구 초대, 내보내기, 나가기/삭제
- 다른 사람이 쓴 메모, 초대, 친구 요청이 **실시간**으로 반영됩니다.
- 모바일에서는 아래쪽 탭 메뉴 + 전체 화면 대화로 바뀝니다.

## 파일 구조

```
index.html              화면 구성
css/style.css           디자인
js/config.js            Supabase 주소와 공개 키
js/app.js               동작 전체
supabase/00_reset.sql   이전 버전 DB를 지우는 SQL (필요할 때만)
supabase/01_schema.sql  DB 테이블·권한(RLS)·실시간 설정
.nojekyll               GitHub Pages 처리용 빈 파일
```

## 1단계. Supabase 설정

### 1-1. DB 만들기
Supabase 대시보드 → **SQL Editor** → New query

- **처음 설치**: `supabase/01_schema.sql` 전체를 붙여넣고 **Run**
- **이전 버전 SQL을 실행한 적이 있다면**: `00_reset.sql` 실행 → `01_schema.sql` 실행
  (⚠️ 기존 메모·친구 데이터는 삭제되고, 가입한 계정은 유지됩니다)

### 1-2. 회원가입 허용 (기본값 확인)
**Authentication → Sign In / Providers**
- **Allow new users to sign up**: 켜짐
- **Email** provider: 켜짐
- (선택) **Confirm email**: 끄면 메일 인증 없이 가입 즉시 로그인. 켜 두면 메일 인증 후 로그인

Supabase 기본 메일 발송은 시간당 발송 수가 적게 제한되어 있습니다. 여러 사람이 가입할 예정이면 직접 SMTP를 연결하거나 Confirm email을 끄는 것을 권장합니다.

### 1-3. 로그인 주소 등록
**Authentication → URL Configuration**
- **Site URL**: `https://내아이디.github.io/저장소이름/`
- **Redirect URLs**: `https://내아이디.github.io/저장소이름/**` 추가

---

## 2단계. GitHub에 올리고 배포

1. GitHub에서 **New repository** 생성 (Public)
2. **Add file → Upload files** 로 이 폴더의 파일과 폴더를 **구조 그대로** 올리고 Commit
3. **Settings → Pages** → Source: **Deploy from a branch**, Branch: **main** / **/(root)** → Save
4. 1~2분 뒤 `https://내아이디.github.io/저장소이름/` 접속
5. 이 주소가 1-3 단계에 등록되어 있는지 확인

## 로컬에서 실행

```bash
cd 이폴더
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```
(파일을 더블클릭해서 열면 동작하지 않습니다)

## 사용 순서 예시

1. 민지, 준호, 서연이 각각 가입
2. 민지: **친구** → 오른쪽 위 사람＋ 아이콘 → 준호·서연 이메일로 요청
3. 준호·서연: 친구 화면의 **받은 친구 요청**에서 수락 → 서로 친구
4. 민지: **메모장** → 오른쪽 위 ＋ 아이콘 → 이름 입력, **준호만** 체크 → 만들기
5. 준호에게 실시간으로 "메모장에 초대되었습니다" 알림 → 메모 주고받기
6. 서연은 민지의 친구지만 이 메모장이 보이지 않음 (초대받지 않았기 때문)
7. 필요하면 민지가 ≡ → 친구 초대에서 서연을 추가

## 보안 관련

- `js/config.js` 의 `sb_publishable_...` 키는 브라우저 공개용이라 GitHub에 올라가도 괜찮습니다.
- `sb_secret_...` / `service_role` 키는 **절대** 넣거나 올리지 마세요.
- 다른 사람의 프로필(이름·이메일)은 친구, 친구 요청 상대, 같은 메모장 참여자에게만 보입니다.
- 친구 추가 시 "가입되지 않은 이메일" 안내가 나오므로, 특정 이메일의 가입 여부는 알 수 있습니다.

## 문제 해결

| 증상 | 해결 |
|---|---|
| "DB 구성이 없습니다" | `01_schema.sql` 실행 |
| 실행 시 "already exists" | `00_reset.sql` 실행 후 `01_schema.sql` 다시 실행 |
| "현재 회원가입이 꺼져 있습니다" | 1-2 단계 Allow new users to sign up 켜기 |
| "가입되지 않은 이메일입니다" | 상대가 먼저 가입해야 친구 요청 가능 |
| 메모장에 친구가 초대 목록에 안 보임 | 친구 요청이 수락되어 서로 친구인지 확인 |
| 실시간 반영이 안 됨 | Database → Publications → supabase_realtime 에 friendships, memos, memo_members, memo_messages 가 있는지 확인. 새로고침하면 최신 상태로 보임 |
